# Шаг 40 — возврат календаря к выбранной дате

Основа: шаг 39 b10ceb5. consultant_create_appointment после POST возвращает
на /account/consultant/calendar/?date=YYYY-MM-DD, если исходная date прошла
существующий разбор datetime.strptime. Дата в URL нормализуется isoformat;
произвольный next/внешний URL из POST не используется.
Это действует при успехе, занятом слоте, пропуске обязательного поля и
неверном времени. При отсутствующей/неверной дате — прежний базовый календарь.
GET, роли, CSRF, тексты сообщений и правила создания записи не менялись.
Правила рабочего расписания/допустимых слотов этим шагом не расширялись.
Модели, миграции, шаблоны и JS не менялись.

## Ручная проверка
В календаре выбрать день, отличный от сегодняшнего, и свободный слот.
Создать тестовую запись: после сохранения должен остаться выбранный день,
новый слот должен быть занят. При повторной попытке время не дублируется,
сообщение о занятом слоте выводится на том же дне.
Миграции и копия БД при установке не нужны: установка меняет только код.
Копии исходников: patch-backups/step40-*/original.
Откат кода не отменяет записи, созданные пользователем через сайт.
Push и развёртывание не выполнялись.
