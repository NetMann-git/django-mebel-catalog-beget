# Шаг 07 — проверки галереи Django admin

## Результат
В /admin/products/product/<id>/change/ встроен тот же шаблон, JavaScript,
CSS и серверные операции, что используются в /catalog/manage/.
Старый inline и отдельное поле image убраны из формы администратора.
Поле image в модели, фотографии, alt, порядок и контрольные суммы сохраняются.
Установка не меняет БД и медиа. Миграции и резервная копия БД не требуются.
Главное фото без записи в галерее по-прежнему отображается и сохраняется.
При создании изделия сначала нажмите «Сохранить и продолжить редактирование».
Сверху формы добавлена ссылка «Фотографии».

Административные URL проверяют is_staff, право изменения изделия и все три права
на фотографии галереи (add/change/delete); затем вызывают общий POST-обработчик
под декоратором ролей менеджера. CSRF, транзакции, проверка очереди и оригиналов
используются без дублирования. Менеджер без is_staff не получает доступ к admin.
Для сотрудников без полного набора прав редактор не показывается, операции
запрещены. Суперпользователь имеет доступ. /catalog/manage/ сохраняет свои права.
Исправлен обнаруженный сбой общей формы у сотрудника только с правом просмотра:
инициализация URL-полей теперь учитывает отсутствие редактируемых полей.

## Автоматически
Linux, Python 3.12, Django 5.2.8, отдельная SQLite и временная папка медиа.
38 тестов успешно:
- apps.products.tests.test_admin_gallery (6 новых тестов);
- apps.products.tests.test_gallery_upload;
- apps.products.tests.test_car_models;
- apps.products.tests.test_manager_slugs.
Проверены: отсутствие вложенных форм и старого поля image, первое сохранение,
побайтовое сохранение оригиналов, дубли, выбор обложки, порядок, удаление текущей
обложки с выбором следующей, возврат в админку, сохранение старой отдельной
обложки, сохранение полей изделия без перезаписи обложки, поддельный image-clear,
права staff/manager/anonymous/view-only, запрет GET, CSRF и привязка токена к изделию.
Исходные тесты загрузки также проверяют частичные ошибки и отказ сохранения.
Django check — 0 ошибок. node --check gallery-manager.js и git diff --check — успешно.

## В браузере
Проверен настоящий HTML, полученный Django test client с тестовым суперпользователем,
и исходные CSS/JS. Внутренний просмотр отдавал сохранённый ответ Django; браузер
не был подключён к рабочей БД. Десктоп 1348px и iframe 390px: карточки фотографий,
пометка обложки, порядок, кнопки и загрузчик. На 390px scrollWidth = clientWidth.
Нажатие загрузки с пустой очередью даёт сообщение «Выберите фотографии для загрузки».
Реальные записи/загрузка файлов проверены Django-тестами, не браузером.
Тестовые изображения и учётная запись в ZIP не входят. Production не проверялся.

## Установщик
На отдельной копии проверены: --check без изменений, --apply, --rollback,
точное восстановление заменённых файлов и удаление новых; отказ при изменённых
исходниках до первой записи, отказ отката после правок, CRLF/LF и побайтовый
откат CRLF. Проверены также установка и откат из распакованного итогового ZIP.

## Ручная проверка
Windows/Python 3.11 и MySQL/Beget непосредственно не проверялись.
В admin откройте изделие, перейдите по ссылке «Фотографии», выберите несколько
своих фото, загрузите, обновите галерею, смените обложку и порядок. Сохраните поля
изделия и проверьте, что обложка осталась. Сверьте публичную карточку и редактор
/catalog/manage/. Для нового изделия сначала сохраните карточку с продолжением.
Галерея сохраняется отдельно; перед её действиями сохраните поля изделия.
