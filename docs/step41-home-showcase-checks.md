# Шаг 41 — главная как рабочая витрина каталога

Основа: шаг 40, commit 3afe844. Сохранены структура, цвета и сетки
утверждённого макета, hero, этапы, материалы, FAQ, форма заявки и якоря.
Главная теперь использует данные существующего каталога и отзывов:

- Шесть категорий: первое доступное главное фото активного изделия,
  сначала с флагом is_featured, затем по убыванию pk. Выбор выполняется
  одним запросом с коррелированным Subquery, без загрузки всего каталога.
  Конфликтные категории пропускаются по прежнему списку проверенных URL.
  Если фото нет, остаётся прежняя иллюстрация из макета.
- Блок #portfolio: первые четыре активных изделия из существующей
  выборки CatalogRepository.featured (флаг «Показывать на главной»).
  Сохраняется её порядок. Фото и название ведут в настоящую карточку;
  выводятся краткое описание либо категория. Нет фото — явная заглушка.
  Это каталог, поэтому заголовок не выдаёт изделия за выполненные проекты.
  Если отмеченных изделий нет, остаются подписанные демонстрационные примеры.
- Блок #reviews: три последних опубликованных отзыва об активных изделиях.
  Текст экранируется, сокращается до 35 слов; автор через прежний
  Review.get_author_name, оценка и ссылка на изделие. Приоритет изображения:
  первое фото отзыва, затем главное фото изделия, иначе без фото.
  При отсутствии отзывов — честное пустое состояние вместо трёх заглушек.

Используются исходные image.url/storage.url с loading=lazy. Файлы не
перезаписываются, производные миниатюры не создаются. CSS object-fit
обрезает только отображение, исходник сохранён. Новые модели, зависимости,
миграции, импорт и массовые изменения БД не нужны. Админка, AJAX-поиск,
галерея, формы заявки и публикация записей не менялись.
