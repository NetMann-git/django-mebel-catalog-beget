# Шаг 77 — убрать модели автомобилей и импорт Encar из интерфейсов

Основа: установленный шаг 76. Миграций нет.
Из Django admin убраны регистрации CarModel и VehicleImportSource.
В кабинете менеджера удалены пункты «Модели автомобилей» и «Импорт из Encar».
Удалены маршруты manage/car-models/ (включая создание, изменение, удаление),
manage/import-encar/ и его обработчик просмотра фотографий пакета.
Прямые GET/POST по этим адресам больше не открывают обработчики (404).
Прямые админские адреса моделей и источников импорта тоже недоступны.

Общий справочник EquipmentOption остаётся для мебельных особенностей.
В его админке убраны столбец, поиск и поле ввода encar_standard_code.
Сохранённое значение поля при обычном или подделанном POST не меняется.
Группы, названия, порядок, активность и выбор опций изделия сохраняются.
Модели, миграции, таблицы, JSON источников, прежние коды и связи изделий
с CarModel не удаляются. Сервисные файлы импорта остаются без web-маршрутов.
Формы изделия/бренды/категории/галерея не переделываются.

Проверки: 30 Django-тестов прошли на SQLite — четыре новых сценария
скрытых инструментов, прямых маршрутов и реестра admin; отсутствие кода
Encar в форме, сохранение его значения при POST, сохранение импортных
данных/связей; также кабинет менеджера, формы изделий, admin-галерея,
очистка фильтров и отключение калькуляторов из предыдущих шагов.
Django check и makemigrations --check --dry-run — OK (No changes detected).
git diff --check и установщик: check/apply/rollback, конфликты до записи,
точное восстановление исходников, LF/CRLF и ZIP — OK.
Windows, MySQL/Beget и браузер здесь не проверялись.

Остановите и заново запустите Django после установки для обновления
реестра admin и URLconf. База и изображения не меняются; копия БД для
этого шага не требуется. Исходники сохраняются в patch-backups/step77-*/original.
Откат возвращает пункты, регистрации и маршруты; после отката тоже
перезапустите приложение. На Beget используйте штатный перезапуск.
