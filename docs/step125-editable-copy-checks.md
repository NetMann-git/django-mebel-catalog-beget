# Шаг 125 — управление текстами сайта

Раздел /account/content/pages/ доступен менеджерам и администраторам через личный кабинет и панель мастерской. Хаб объединяет новый редактор с существующими контактами, командой, клиентами, каталогом и фотографиями категорий.

Шесть разделов: главная, кухни на заказ, о мастерской, услуги, материалы, общий callback-блок. Редактируются главные заголовки и вводные тексты, SEO-заголовки/описания, описания блоков «О мастерской» и материалов, описания всех существующих услуг, вопросы/ответы главной и кухни с видимостью каждого пункта. Названия услуг и тематические иконки сохранены. Ссылки, формы, структура страниц, фотографии и галереи не меняются редактором.

Исходные значения перенесены из текущих шаблонов в copy_registry.py. При отсутствии записи используются они же; миграция не заполняет таблицу и не перезаписывает прежнее содержимое. Вопросы используют существующие слоты, порядок слотов фиксирован; слот можно скрыть флажком. Новые вопросы можно внести в существующие слоты. Это редактор обычного текста, не HTML-конструктор и не менеджер произвольных страниц.

EditablePage хранит черновик отдельно от опубликованных значений. «Сохранить черновик» не меняет публичную страницу. «Сохранить и опубликовать» сохраняет введённые значения и показывает их посетителям. Фиксируются время публикации и последний редактор. Предпросмотр /account/content/pages/<key>/preview/ отображает сохранённый черновик через настоящий публичный шаблон; доступен только сотрудникам, no-store и X-Robots-Tag noindex. Параметры публичного URL не открывают черновики. HTML из текста экранируется, переносы отображаются безопасно. Настройки читаются один раз на раздел в пределах запроса, без межпользовательского кеширования черновиков.

Номер редакции и блокировка записи защищают от молчаливой перезаписи устаревшей формой. При конфликте 409 введённые поля остаются в форме; предлагается открыть свежий редактор. В Django Admin значения доступны для просмотра со ссылкой в редактор; прямое изменение JSON отключено.

Миграция home.0011_editable_page создаёт одну новую таблицу. До migrate выполните:
`python manage.py backup_before_content --settings=config.settings.dev`
Копия SQLite/MySQL сохраняется штатным database_backup в BASE_DIR/patch-backups с префиксом step125-before-content. При ошибке копирования миграцию не выполнять.

Проверено:

- 25 тестов редактора, предпросмотра всех шести разделов, публикации и последующих черновиков, доступа, CSRF, конфликта, ошибочных действий, FAQ, услуг, callback и XSS; также существующие тесты публичных услуг, мастерской, материалов, кухонь и общей формы.
- Django check без ошибок; makemigrations home --check --dry-run без расхождений.
- На копии базы шага 124 сохранена проверенная предмиграционная SQLite. После миграции обращения, закрытые фото, заказы, события, изделия и контакты совпадают с исходными. Новая таблица пуста; integrity_check копии — ok.
- Все шесть редакторов и шесть закрытых предпросмотров возвращают 200; локальные ресурсы существуют, ID элементов уникальны.
- Установщик check/apply/rollback и контрольные суммы ZIP, включая текстовые окончания Windows.

Визуальная браузерная проверка и MySQL-миграция здесь не выполнялись. Полная история предыдущих редакций текстов не добавлялась: хранятся текущие черновик и публикация. Существующие данные не импортируются и не изменяются при установке.

Откат установщика возвращает файлы, а не БД. Обратная миграция удаляет таблицу текстов: после заполнения не выполнять без свежей резервной копии. Следующий пункт общего плана — сквозная проверка перед запуском.
