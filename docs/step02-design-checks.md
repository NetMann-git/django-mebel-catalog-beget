# Шаг 02 — главная по дизайн-макету

Основа: шаг 01, Git 36674f5. Основной визуальный ориентир — первый макет 1.jpg.
Вся главная: шапка, фотобаннер, 6 категорий, преимущества, 4 этапа,
примеры решений, материалы, отзывы, FAQ, форма и подвал.
Домашняя страница больше не подключает автомобильные секции и их CSS/JS.
Старые файлы остаются на месте. Каталог, кабинеты, URL, модели и данные сохранены.
В base.html добавлены переопределяемые блоки SEO и favicon с прежними значениями
по умолчанию. Для главной заданы мебельные метаданные и отключена автомобильная иконка.

## Источники и ограничения
- furniture-reference-01.jpg = исходный 1.jpg, 779×1920.
- furniture-reference-02.jpg = исходный 2.jpg, 1024×1536.
- Оба JPG скопированы побайтно: без конвертации, сжатия и изменения размера.
- SVG viewBox показывает области фотографий исходных макетов; надписи сайта,
  кнопки, сетки, форма и меню реализованы в HTML/CSS, а не картинкой всей страницы.
- Детализация ограничена присланными макетами: это не исходные полноразмерные фото.
- Примеры явно обозначены как демонстрационные; реальные отзывы не придуманы.
- Контакты, бесплатный замер, сроки «от 10 дней», гарантия «5 лет» из макета
  не перенесены как утверждения о мастерской.
- Карточки категорий пока ведут к форме обсуждения проекта. Каталог по /catalog/
  сохранён в исходном виде; это пока не каталог мебели.
- Форма использует существующие поля name/phone, CSRF, honeypot и обработчик.
  Вариант мебели не добавлен как неподдерживаемое сервером поле.
- Существующие правовые страницы ещё требуют адаптации к мебельной мастерской.

## Автоматическая проверка
На отдельной тестовой копии, Linux / Python 3.12 / Django 5.2.8:
- manage.py check — no issues;
- главная, каталог, вход и вход в админку — HTTP 200;
- одна H1, внутренние якоря и пути статики корректны;
- на главной нет автомобильных текстов;
- неправильный телефон — HTTP 400 с ошибкой поля;
- POST без CSRF — HTTP 403;
- корректная заявка сохраняется в тестовую SQLite; внешние уведомления замокированы;
- JS syntax check — успешно;
- --check без записи, --apply, --rollback и повторная установка — успешно;
- отказ при отличиях исходников и изменениях после установки;
- CRLF/LF принимаются, откат восстанавливает точные исходные байты;
- новые файлы удаляются при откате, исходные JPG совпадают побайтно.

## Браузерная проверка
Проверен статический HTML, полученный реальным рендером Django, в Chrome:
- широкий экран: viewport 1348 px; первый экран, карточки, средние секции,
  FAQ, форма и подвал;
- узкий экран: iframe шириной 390 px (доступная область 375 px со скроллбаром);
- меню открывается и закрывается при выборе якоря;
- FAQ раскрывает ответ;
- пустая форма показывает ошибку телефона и сообщение статуса;
- горизонтального переполнения нет: scrollWidth == clientWidth на обоих размерах.
Браузерный POST не проверялся на статическом предпросмотре; сохранение и CSRF
проверены отдельно через Django test client на тестовой БД.
На реальном телефоне, Windows Python 3.11 и production проверки не выполнялись.
Нужна оценка сходства с образцом в браузере пользователя и проверка реальной формы
после установки. Сам патч БД не меняет и миграций не содержит.
