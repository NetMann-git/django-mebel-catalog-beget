# Шаг 122 — единая заявка на расчёт

Следующий пункт согласованного плана. Новая страница `/request/` принимает запрос без выбора изделия. Общие EstimateRequestForm, estimate_fields.html и save_estimate используются этой страницей, направлением «Кухни на заказ» и существующими формами изделия/похожего проекта.

Поля: имя, телефон, город, email, направление, планировка кухни, три размера в сантиметрах, ориентир бюджета, пожелания, фото. Обязательны имя и телефон. На странице кухни сохраняются её названия размеров и выбранная планировка. Выбор направления управляет показом планировки кухни; для окон AJAX-форм используется делегирование и наблюдение за добавлением полей. Без JS поля доступны, а сервер применяет планировку только для кухни.

Фото проходит существующий валидатор SimilarProjectForm (JPEG/PNG/WebP, до 5 МБ и 24 Мп, без анимации), сохраняется JPEG в закрытом CallbackReferencePhoto. Обращение и фото сохраняются одной транзакцией. Ошибка вложения не оставляет обращение. Уведомления отправляются существующим обработчиком после сохранения; его изоляция ошибок сохранена.

`/request/?direction=kuhni` выбирает направление. `/request/?product=ID&purpose=similar` связывает запрос с опубликованным изделием. purpose принимает similar/order/detail с прежними источниками similar_project/product_order/product_detail; общий запрос остаётся site_callback. Идентификатор берётся из URL и проверяется на публикацию; скрытые, отсутствующие и некорректные изделия дают 404. Подложный ID в теле формы игнорируется. Произвольных return/next-переходов нет.

Страница не индексируется и не кеширует личный результат. Успешный POST перенаправляет на GET с номером заявки из сессии; обычное обновление не повторяет запись. Ошибки сохраняют текст; фото необходимо выбрать снова. CSRF и поле-ловушка работают.

Старые адреса и модальные формы изделия сохранены, теперь используют общие поля и обработчик, включая размеры/бюджет/фото. Из них можно открыть отдельную страницу с тем же изделием и назначением обращения. В услугах и каталоге кнопки обсуждения ведут на общую заявку; ссылка добавлена в подвал и общую секцию обратного звонка. Короткий обратный звонок сохранён. Даже с общей страницы расчёта он сохраняет связь с выбранным изделием.

Миграций и импорта БД нет. Установка поверх шага 121 с уже выполненной products.0012. Новых зависимостей нет. Код установщика сохраняет исходные файлы в patch-backups.

Проверено: 51 тест (единая форма, кухни, старые обращения, похожий проект, уведомления, общая callback-секция, услуги и карточки изделий); Django check; синтаксис JS; установка/откат файлов и ZIP. Покрыты разные источники запроса, закрытое фото, сбой вложения, ошибки полей, ложный ID, скрытые изделия, обновление после отправки, ловушка и CSRF.

Браузерная проверка в среде недоступна; адаптивные стили и клиентское переключение планировки требуют проверки в браузере пользователя. Существующие записи обращений не переносятся и не изменяются.
