# Шаг 03 — мебельные категории

Основа: шаг 02, коммит d50db4d.
Использована существующая Category и существующий GET-фильтр category=<ID>.
Категории: Шкафы (shkafy), Кухни (kuhni), Стеллажи (stellazhi), Полки (polki),
Гардеробные (garderobnye), Другая мебель (drugaya-mebel).
Карточки главной получают ссылки только на точные совпадения справочника.
До подготовки категории или при конфликте карточка сохраняет ссылку на форму.
«Все направления» открывает существующий каталог. Дизайн главной не изменён.
Страница самого каталога пока автомобильная; её адаптация — отдельный шаг.

Команда prepare_furniture_categories требует --check или --apply.
Она не переименовывает, не удаляет и не перемещает существующие записи.
Конфликт названия/slug, включая регистр и крайние пробелы, останавливает весь импорт.
Повторное применение не создаёт дубликатов и не делает лишнюю копию БД.
Категории создаются транзакционно, затем сбрасывается только кэш фильтров.

Снимки: общий модуль SQLite Backup API + PRAGMA integrity_check; для MySQL —
mysqldump/mariadb-dump с --single-transaction и проверкой успешного завершения.
При отсутствии утилиты или наличии не-InnoDB таблиц запись MySQL запрещена.
Пароль MySQL передаётся процессу через окружение, не командную строку и не отчёт.
Существующая команда backup_catalog_sqlite использует тот же проверяемый механизм;
её назначение и стандартный префикс before-migration сохранены.

Проверено на отдельной копии Linux, Python 3.12, Django 5.2.8:
- 9 автоматических тестов — OK;
- --check не создаёт категории и резервные копии, пишет только JSON-отчёт;
- сохранение старой категории и повторный --apply без дубликатов;
- конфликты названий и slug, отказ при ошибке снимка;
- откат частичной записи при IntegrityError;
- переходы главной и выборка существующим фильтром;
- защищённый от перезаписи файл отчёта;
- снимок SQLite с WAL и восстановление данных из него;
- параметры mysqldump, отсутствие пароля в аргументах и отказ при ошибке — mock;
- на файловой тестовой БД: create=6, skip=0; после применения create=0, skip=6;
- реальный снимок до добавления содержал 0 категорий, integrity_check=ok;
- восстановление этого снимка в отдельную БД — успешно;
- все 6 ссылок главной, каталог с фильтром, вход и админка — HTTP 200;
- установщик: --check, --apply, --rollback, защита от конфликтов, CRLF/LF;
- Django check — no issues.
MySQL/Beget и Windows Python 3.11 не проверялись вживую.
Браузерная проверка в этом шаге не проводилась; внешний вид не менялся.
Нужно вручную проверить переходы шести карточек после применения данных.
Миграций нет. Установка файлов сама по себе базу не меняет.
