# Шаг 127 — проверка перед запуском

Добавлена команда `audit_furniture_launch`. Проверяет миграции, 13 публичных страниц, до 20 карточек изделий (настраивается через `--limit 1..100`), H1 и повторяющиеся id, наличие ссылки на заявку в HTML главной, закрытие пяти служебных разделов от гостей, отсутствие двух старых публичных маршрутов, robots/sitemap/иконки и наличие локальных ресурсов HTML. Проверяет исходные фото активных изделий и их галерей, категорий, опубликованных клиентов и команды; опубликованный телефон; ошибочный выбор демонстрационных изделий для портфолио; корректность включённых видеоотзывов; неопубликованные черновики.

`--output patch-backups/launch-audit.json` сохраняет JSON. Ошибки дают ненулевой код завершения; замечания перечисляются отдельно. Отчёт не содержит секретов, телефонов, содержимого обращений или заказов. Команда не отправляет формы и уведомления, не делает сетевых запросов. Изменения БД от GET (сессии и метаданные миниатюр) откатываются; файлы кеша миниатюр могут создаваться обычным рендерингом.

`--deployment` дополнительно проверяет DEBUG, HTTPS SITE_URL, ALLOWED_HOSTS, длину/разнообразие SECRET_KEY и secure cookies; ресурсы статики ищет в собранном хранилище. Это проверка настроек и Django, а не реального HTTPS, DNS, почты, доставки Telegram/MAX, nginx или прав внешнего пользователя. Не проверяет все ссылки и фоновые изображения внутри CSS; H1/id проверяются в серверном HTML, без выполнения JavaScript. Публикация телефона не доказывает, что номер принадлежит мастерской.

## Исправления

- Видеоотзывы и команда снова выводятся на мебельной главной в отдельных адаптивных секциях. Фото сотрудников — производные изображения 400/800 px, без оригиналов в превью. Старые статические фото сотрудников не используются.
- Для видео добавлен отдельный флаг `show_video_on_home`, по умолчанию выключенный. Старые автомобильные ролики остаются скрытыми. В кабинете: «Содержимое сайта → Клиенты → редактировать»: ссылка Rutube, публикация карточки и «Показывать видеоотзыв на главной». Встроенное видео загружается после согласия на внешнее содержимое. Пустые секции не выводятся.
- В восьми обработчиках клиентов/команды проверяется адрес возврата: внешний URL заменяется списком соответствующего раздела; внутренние фильтры сохраняются.
- В production по умолчанию включены secure session/CSRF cookies. Локальная HTTP-разработка не меняется. Автоматические HTTPS-перенаправления и HSTS не включались без проверки конфигурации хостинга.
- Создаётся каталог logs перед настройкой файлового логирования: чистая копия проекта больше не падает из-за отсутствующей директории.

## Перед установкой

Патч поверх шага 126. Есть миграция home.0012. Сначала примените файлы, затем `backup_before_launch`, затем `migrate`. Резервная копия записывается в `<корень проекта>/patch-backups/step127-before-launch-*.sqlite3` или `.sql`. Если копия не создана, миграцию не запускайте. Для MySQL используется существующий проверенный механизм mysqldump/mariadb-dump; сам MySQL в этой среде не проверялся. Откат установщика возвращает файлы, но не БД; согласуйте схему отдельно при откате.

На сервере используйте его настройки, обновите собранную статику и перезапустите приложение. После установки запустите аудит на фактических данных. Отсутствующие фото нужно восстановить из своих резервных копий. Реальную отправку заявок, уведомления, мобильную вёрстку, cookie-согласие и доступ по HTTPS проверьте в браузере: здесь визуальная браузерная проверка недоступна.

## Полный исторический набор: 705 тестов

Итог: 645 прошли, 11 падений проверок, 49 ошибок. До изменений было 699 тестов, 14 падений и те же 49 ошибок. Три падения home исправлены, шесть новых тестов прошли; новых падений не появилось.

49 ошибок относятся к тестам отключённых автомобильных маршрутов: калькуляторы, управление моделями авто, импорт Encar/ZIP. Причина — NoReverseMatch для больше не существующих имён URL. Эти маршруты намеренно не восстанавливались.

11 оставшихся падений требуют актуализации ожиданий/фикстур под реализованные шаги:

- test_furniture_categories: теперь у кухонь отдельная страница направления, а не #callback.
- test_furniture_comparison, test_furniture_history, recommendations.tests, users.test_furniture_favorites, wishlist.tests: требуют URL оригинального фото, несмотря на переход к производным изображениям; фикстуры указывают несуществующие файлы. Следует создавать реальные тестовые изображения и проверять размеры/ссылки миниатюр, сохранив остальные утверждения.
- test_furniture_sitemap: список не учитывает /services/kitchens/.
- test_repository: ожидает удалённые из фильтров colors/collections/silhouettes.
- users.test_furniture_manager: ожидает каталог первым пунктом, хотя первой теперь идёт страница содержимого.
- users.test_furniture_profile и test_furniture_registration: собирают поля всех форм страницы, включая общую форму обратного звонка; нужно ограничить выборку основной формой, сохранив проверки её полей.

Нельзя считать полный набор зелёным или запуск подтверждённым. Отдельная следующая задача — привести тестовую инфраструктуру к мебельному профилю, без отключения действующих проверок мебели.
