## Исходники

База: ed35de21e12cb8fea937bb92a2e9ac42dcec0426 — установленный шаг 11.
Код совпал с результатом предыдущего шага. Production не менялся, push не выполнялся.

## Результат
Список /catalog/manage/categories/, создание, редактирование и подтверждение
удаления оформлены в существующем furniture_base LUSTRID.RU. На телефоне строки
списка превращаются в карточки. Сохранены все поля, ID, URL и прежние действия.
Есть прямые ссылки на публичный каталог с фильтром по прежнему ID категории.
Количество изделий учитывает опубликованные и неопубликованные записи — это
уточнено в интерфейсе. У занятой категории нет кнопки подтверждения удаления.
Сообщение при запрещённом POST теперь говорит об изделиях, а не автомобилях.

Для существующих шести категорий главной показано предупреждение: homepage
использует точные пары название/код из FURNITURE_CATEGORIES. Изменение пары либо
удаление категории отключает прежний переход из её карточки в каталог.
Использован готовый реестр, без дублирования названий/кодов и без изменения логики
главной. Предупреждение вычислено до валидации формы, поэтому не исчезает после
ошибочного POST, даже когда Django изменяет несохранённый instance в памяти.
Вносить изменения в категории главной ради проверки не требуется.

Форма и её валидация, генерация латинского кода на сервере, права, транзакции,
защита CSRF, проверка занятости при POST и сброс кеша остаются прежними.
Модели, текущие категории, их названия/коды и связи изделий при установке не меняются.
«Тип изделия», галерея и оригиналы фотографий не затрагиваются.
Миграции, импорт и резервная копия БД не нужны: патч меняет только код/шаблоны/CSS.

## Автоматические проверки
Linux, Python 3.12, Django 5.2.8, отдельная SQLite и временные папки.
20 тестов успешно:
- apps.products.tests.test_furniture_category_manager — 6 новых;
- apps.products.tests.test_category_management — прежние сценарии справочника;
- apps.products.tests.test_furniture_categories — регрессия категорий и переходов.
Проверены: число изделий с черновиками; ссылки по исходным ID; GET всех экранов
не меняет категории/изделия/переходы главной; предупреждения для категорий главной
и их сохранение после ошибочного POST; создание без JavaScript с транслитерацией;
редактирование с сохранением ID/кода и привязки изделия; обязательные поля,
уникальность и ошибки; запрет удаления занятой категории, в том числе через
прямой POST и после добавления изделия между GET подтверждения и POST;
CSRF; аноним/клиент/консультант/staff без роли не получают доступ; manager/admin
по прежним тестам и суперпользователь; GET не удаляет, пустая категория удаляется
только после POST. Операции удаления тестировались только на одноразовой БД.
Внешние уведомления не отправлялись. Django check — 0 ошибок, git diff --check — OK.

## Ручная проверка
Откройте «Категории» на панели менеджера и обновите Ctrl+F5. Проверьте количество
изделий, открытие каталога, формы и мобильный вид. Создание/редактирование проверяйте
на отдельной тестовой категории. У одной из шести категорий главной откройте форму
и проверьте предупреждение, затем отмените, не меняя название/код. У занятой категории
откройте подтверждение: удаление должно быть недоступно. Удалять реальные категории
для проверки не требуется; защищённость POST уже проверена автотестами.
